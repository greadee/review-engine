# Sprint 1.1.0 — post-v1 hardening (Common Rat Named patch)

## Goal

Close the gap between the engine's documented guarantees and what it actually
enforces. The post-v1 audit found that several safety claims are not enforced
end-to-end; this sprint makes each one deterministic and CI-enforced with a
hermetic regression test.

## Context

This sprint is part of the **1.1 Common Rat** line; see
[`docs/versioning.md`](../versioning.md) for the version/animal-rank scheme.

The v1 claim — *safe, deterministic, evidence-based PR review* — holds
functionally, but the audit (issues #9–#16) found that:

- a blocking finding can be silently downgraded to unverified and never fail the
  check (#9);
- static-analyzer subprocesses inherit the provider key and GitHub token (#10);
- the PR summary comment is keyed per run, so a PR accumulates one comment per
  commit (#11).

The remainder are correctness/robustness items.

## Scope

**Must fix**

- #9 Evidence verification silently un-blocks static analyzer findings
- #10 Analyzer subprocesses inherit the provider key and GITHUB_TOKEN
- #11 Summary comment is keyed per run, so a PR accumulates comments

**Should fix**

- #12 Whole-repo audit/sprint profiles always report INCOMPLETE coverage
- #13 Python compile findings can never block (no file/line evidence)
- #14 Archive JSON uses mixed-case keys (Run has no json tags)
- #15 `revu run --dry-run` still writes tracking state
- #16 No provider retry/backoff for rate limits and transient errors

## Approach

Test-first, one issue per commit. Each commit adds a hermetic (no network, no
live provider) regression test that fails on the current code and passes with
the fix. CI runs `go test ./...`, so the guarantees stay enforced.

## Sequencing

1. **#9, #10, #11** — guarantee enforcement (must land first).
2. **#12, #13** — coverage/blocking correctness.
3. **#14, #15** — schema and CLI UX.
4. **#16** — provider reliability.

## Definition of done

- Every guarantee above has a deterministic test proving it (the specific test
  is named in each issue).
- `gofmt -l .` clean, `go vet ./...` clean, `go test ./...` green.
- The seeded corpus and the fork-safe integration harness continue to pass (no
  behavioural regressions).

## Size

Roughly 4–5 engineer-days total (S + S + S, then S + S + S + XS + M).

## Out of scope

Items recorded in [`docs/limitations.md`](../limitations.md): GitHub Enterprise
permalinks, multi-provider routing, and criteria-evidence strength beyond
"reviewable reference".
