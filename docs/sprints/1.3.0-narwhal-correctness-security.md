# Sprint 2 — v1.3.0 Narwhal

**Release purpose:** Correctness & Security

**Status:** in progress
**Branch:** `1.3-correctness-security`
**Milestone:** `1.3 Narwhal` (milestone description: “Release purpose: Correctness & Security”)
**Entry dependency:** `v1.2.0` Common Chimpanzee published with the Restore release note
**Release note:** finalized at release time from the verified sprint results

## Sprint goal

Make the review result trustworthy under adversarial and real-world input. The sprint closes correctness debt that undermines the product claim and replaces asserted accuracy with measured accuracy.

## Why this sprint

The Restore sprint makes the project honest about what it ships. This sprint makes the engine itself more trustworthy. The highest-risk remaining gaps are:

- the review diff can include unrelated base-branch changes;
- cross-run tracking is not persisted in CI, so lifecycle data is fictional there;
- prompt-injection resistance is asserted but the deterministic corpus does not test a real model;
- issue verification accepts author-supplied references without checking whether the referenced work exists or is relevant;
- audit/sprint scope can bypass ignore rules and can exceed bundle limits;
- several comment-rendering paths still accept untrusted text without the shared sanitizer.

The sprint is deliberately about evidence, not new surface area.

## Success measures

- PR scope is computed from the merge base and is tested with a moved base branch.
- Two CI runs restore the same tracking state and produce correct `new`, `ongoing`, `resolved`, and `regressed` transitions.
- A real pinned model, DeepSeek V4.1 Flash 1017 (`deepseek v4.1 flash 1017`), is evaluated against the labeled corpus, with precision, recall, severity accuracy, cost, and latency published.
- Prompt-injection tests exercise the same pinned model, not only the oracle.
- Issue verification checks referenced work through the GitHub API and records why a reference counts.
- Every generated GitHub comment path uses the shared sanitizer.
- Audit/sprint ignore rules are honored and whole-repo scans are bounded.
- The CLI has meaningful test coverage for review-critical paths.
- No open P0/P1 findings; residual risks are documented plainly.

## Work items

| ID | Working title | Outcome | Acceptance criteria |
|---|---|---|---|
| C-01 | Merge-base review scope | A PR review contains only the PR’s changes | PR profiles compute scope from the merge base; a test where the base branch advances after branching shows no reverse changes; the change is documented for `pr` and `impact` |
| C-02 | Persisted tracking state | Lifecycle and delta behavior is real in CI | The GitHub workflows restore and save `.review-state` (Actions cache, artifact, or bot-branch state); two-run integration tests prove `new` → `ongoing`, disappearance → `resolved`, and reappearance → `regressed`; state is scoped so one PR cannot mark another PR’s findings resolved |
| C-03 | Prompt-injection hardening | Repository text is treated as data, not instructions | The prompt states explicitly that source and comments are untrusted; file boundaries are unambiguous and resistant to spoofing; a real-model adversarial suite using DeepSeek V4.1 Flash 1017 covers “ignore instructions,” forged findings, suppression, and delimiter spoofing; failures are reported, not silently approved |
| C-04 | Real-model evaluation | Accuracy claims are measured, not asserted | DeepSeek V4.1 Flash 1017 (`deepseek v4.1 flash 1017`) runs against the labeled corpus; the report records the exact provider model identifier and settings; it includes precision, recall, P0/P1 recall, severity accuracy, false positives, invalid evidence, latency, and token/cost data; methodology and known gaps are published; CI keeps the hermetic oracle test and the real-model test is a separate, budgeted gate |
| C-05 | Issue evidence validation | “Verified” criteria cite work that actually exists and relates to the issue | Referenced PRs, issues, and commits are resolved through the GitHub API; merged/closed state, repository, and touched areas are checked; tests cover unrelated references, unmerged work, fake SHAs, and hex-looking words; the release notes explain that evidence remains reviewable, not proof |
| C-06 | Comment sanitization | Every bot-authored comment uses the shared safe renderer | Issue criteria, finding titles, file keys, group headings, and reconcile text are escaped/neutralized; regression tests attempt HTML, mentions, images, backtick breakouts, and control characters; no direct `fmt.Fprintf` path posts untrusted text |
| C-07 | Audit/sprint scope and limits | Whole-repo scans honor configuration and bounded resources | Ignore rules apply to audit/sprint; file count and byte limits are consistent with bundle validation; an oversized repository produces a clear incomplete/limit result rather than a bundle that finalize rejects; tests cover a repository above the file cap |
| C-08 | Profile behavior | The five advertised profiles have honest, distinct behavior | `sprint` uses the requested commit range; `impact` has a defined touched-subsystem scope or is removed from the advertised set; scope tests cover each profile; README and action docs match |
| C-09 | Analyzer correctness | Static analysis is scoped and resilient | Analyzer subprocesses have timeouts; unusual filenames are handled safely; build/type-check findings are scoped to changed packages where feasible; missing tools degrade to incomplete coverage rather than silent approval; residual network/secret risks are documented |
| C-10 | CLI test suite | Review-critical CLI behavior is tested | Table-driven tests cover `run`, `collect`, `finalize`, `issue`, config errors, exit codes, dry-run, persist policy, and comment paths; `cmd/revu` coverage is materially above the current 1.1% and has a documented floor |
| C-11 | Parser and response robustness | Malformed or hostile model output cannot exhaust the runner or produce unsafe results | JSON extraction is bounded; output/token budgets are enforced; context cancellation is honored; retry exhaustion is distinguishable from a clean result; pathological responses have tests |
| C-12 | Consistency cleanup | Token, endpoint, and dead-code inconsistencies are removed | `file-issue` and `reconcile` honor the configured token; `eval` uses the endpoint allowlist; unused `AuthenticatedLogin`/evaluation APIs are removed or justified; the CLI has one GitHub client construction path |
| C-13 | Security CI | Known vulnerability classes are gated | `go test -race` (where supported), `staticcheck`, `govulncheck`, and CodeQL or equivalent run on the supported matrix; Dependabot covers Go modules and actions; failures are release-blocking |
| C-14 | Residual-risk register | Users can see what the engine cannot prove | A plain-language document records evidence limitations, model nondeterminism, analyzer coverage, and unsupported environments; the README links it; every open risk has an owner and target release |
| C-15 | Configurable semantic batch limits | Operators can tune request size without changing engine code | `review.maxBatchFiles` and `review.maxBatchBytes` load from `revu.yaml`, profile overrides, environment, and action inputs; `0` keeps the automatic defaults (25 files / 150000 bytes, or 8 / 80000 with reasoning tokens); negative values are rejected; config and reviewer tests cover explicit and automatic behavior; docs and examples are updated |

If scope must be reduced, keep C-01 through C-07, C-10, and C-14; move C-08/C-09/C-11/C-13 to the Stability sprint without removing them from the roadmap.

## Release note contract

**Required title:** `v1.3.0 Narwhal`

**Required opening:** “This is the **Correctness & Security** release. Its purpose is to make review behavior correct under real repository conditions and measurable under adversarial input.”

The note must cover:

- **Purpose:** why correctness and security are the theme.
- **Highlights:** merge-base scope, persisted state, prompt-injection defenses, real-model results, issue-evidence validation, sanitized comments, bounded audit scans.
- **Measured accuracy:** the methodology, corpus size, DeepSeek V4.1 Flash 1017 (`deepseek v4.1 flash 1017`) model identifier and settings, precision/recall, false positives, invalid evidence, cost, and latency.
- **Behavior changes:** lifecycle state now persists; audit ignores are enforced; any profile changes.
- **Known limitations:** model false positives/negatives, unsupported ecosystems, evidence that remains human-reviewable.
- **Upgrade notes:** cache/state permissions, any new config keys.
- **Verification:** real-model report, adversarial suite, two-run state test, oversized-repository test, CLI coverage.

The note must not describe the oracle corpus as a model-accuracy result.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Real-model evaluation is expensive or noisy | Cap the evaluation budget; publish the model, settings, and methodology; keep hermetic invariants in CI |
| Prompt-injection hardening produces false confidence | Test against the real model, report failures, and keep the human-review limitation visible |
| State persistence introduces permissions or cache-key mistakes | Use scoped cache keys per repository/PR; test two-run behavior; never let one PR resolve another’s findings |
| Issue evidence validation becomes a new source of false closures | Default to “unverified” when the API cannot prove relevance; require explicit reviewer override for ambiguous cases |
| Audit limits surprise users | Publish the limits and the incomplete-result behavior in the release note and docs |
| Scope creep into feature work | No new languages, no hosted service, no new providers. New capabilities need a separate decision |

## Definition of done

- Merge-base scope is implemented and tested.
- Tracking state survives a CI restart and produces correct lifecycle transitions.
- Prompt-injection tests run against a real model and are documented.
- Real-model metrics are published with methodology and cost.
- Issue evidence is checked through the GitHub API.
- Every bot comment path uses the shared sanitizer.
- Audit/sprint scans honor ignore rules and bounded limits.
- Semantic batch limits are configurable and documented without changing defaults.
- Profile behavior matches documentation.
- CLI coverage has a documented floor and review-critical tests.
- Security CI runs and is release-blocking.
- Residual risks are documented.
- `v1.3.0` is tagged with the required title and purpose statement; `v1` moves to it.
