# v1.3.0 Narwhal

**Status:** draft — not for publication. Finalize after Sprint A and Sprint B
are complete and the release metrics are rechecked.

**Purpose:** Correctness & Security

This is the **Correctness & Security** release. Its purpose is to make review
behavior correct under real repository conditions and measurable under
adversarial input.

## Highlights

- PR review scope is computed from the merge base.
- CI lifecycle state is scoped per pull request and profile.
- Semantic request batching is configurable through `review.maxBatchFiles` and
  `review.maxBatchBytes`, action inputs, and environment overrides.
- Repository text is treated as untrusted data, with per-request nonce file
  boundaries and adversarial corpus fixtures.
- The pinned DeepSeek V4.1 Flash 1017 (`deepseek-flash`) evaluation is published
  in [`docs/evaluation/1.3.0-narwhal.md`](../evaluation/1.3.0-narwhal.md).
- Issue acceptance evidence resolves PRs, issues, and commits through the GitHub
  API and checks merged/closed state and touched areas.
- `audit` and `sprint` scans honor ignore rules and stay inside the bundle's
  file, per-file, and total-byte ceilings; limit hits produce an honest
  incomplete result.
- `sprint` is range-based: it reviews files changed in the requested commit
  range instead of the whole repository.
- `impact` has a defined touched-subsystem scope: changed files plus files in
  the directories that contain them.
- Static analyzer subprocesses have timeouts, safe filename handling, and
  changed-package Go scoping. Missing tooling produces an incomplete analyzer
  coverage gap.
- The `cmd/revu` test suite covers command exit codes, review commands,
  issue/reconcile comment paths, dry-run, persist policy, and config errors, with
  a CI-enforced 60% coverage floor.
- Provider responses and JSON extraction are bounded; context cancellation stops
  semantic batches; retry exhaustion is distinguishable from an empty result.
- `file-issue` and `reconcile` honor the configured GitHub token, `eval` enforces
  the provider endpoint allowlist, and GitHub client construction is centralized.
- CI gates race-enabled tests, `staticcheck`, `govulncheck`, and CodeQL;
  Dependabot covers Go modules and GitHub Actions.

## Behavior changes

- A `#PR` or commit reference no longer satisfies an issue criterion merely
  because it is present in the text. It must resolve, be merged/closed where
  applicable, and touch the issue's areas.
- A hex-looking word is rejected unless it resolves as a real commit.
- Evidence remains reviewable, not proof: the API can show that referenced work
  exists and is related, but it cannot prove that the work semantically
  satisfies the criterion. A human reviewer remains responsible for that
  judgment.

## Known issues

- The real-model evaluation is probabilistic. Accuracy is a snapshot for the
  pinned model and corpus, not a guarantee.
- The corpus is synthetic and small; it measures the narrow PR-review claim.
- GitHub Enterprise permalinks are not supported.
- Broader stability evidence is the theme of `v1.5.0`.
- The [residual-risk register](../residual-risk-register.md) records every open
  risk with its owner and target release.

## Verification

- `gofmt -l .`, `go vet ./...`, and `go test ./...` pass.
- The deterministic oracle corpus meets its release thresholds.
- The pinned-model report is published at
  [`docs/evaluation/1.3.0-narwhal.md`](../evaluation/1.3.0-narwhal.md).
- Issue-evidence tests cover unrelated references, unmerged work, fake SHAs, and
  hex-looking words.
