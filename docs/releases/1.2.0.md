# v1.2.0 Common Chimpanzee

**Purpose:** Restore.

This is the **Restore** release. Its purpose is to restore confidence in the release surface and close the immediate safety gaps found in the v1.1 audit.

## Highlights

- Collect policy is read from the base revision. A pull request cannot disable static analysis, shrink scope, or turn an empty scope into an approval.
- Finalize independently verifies the bundle against the pull request changed files.
- Archive writes refuse the default branch and the pull request head branch.
- The summary comment is updated in place without `GET /user`; the default `GITHUB_TOKEN` is sufficient and no PAT is required.
- Provider requests use bounded retries for rate limits, timeouts, transient network failures, and server errors.
- Token usage is read from the provider's `prompt_tokens`, `completion_tokens`, and `total_tokens` fields.
- `revu config` redacts credentials.
- `revu version` reports the release or development revision, and the CLI exposes `--static` and `--semantic`.
- Repository governance includes protected `main`, CODEOWNERS, a private security policy, and SHA-pinned third-party actions.
- The committed local development provider configuration is removed; shipped configuration uses a public endpoint.

## Behavior changes

- Review policy (`ignore`, static/semantic toggles, limits, rubric, block threshold, and coverage threshold) comes from the base revision.
- PR and impact finalization requires `--repository` and `--pr` so the trusted side can verify scope.
- One PR has one stable summary comment. The archive remains the history of findings across runs.
- Archive targets must be a dedicated bot branch.

## Known issues

- CI lifecycle tracking is per-job until persistent state lands in 1.3.
- Duplicate marker comments created by earlier append-per-run releases are not removed automatically.
- GitHub Enterprise permalinks are not supported.
- Real-model accuracy evidence and prompt-injection results are the theme of `v1.3.0`.
- Stability and fragility evidence are the theme of `v1.5.0`.

## Upgrade notes

- Move review policy that was previously changed in the pull request to the base branch or a trusted global/workflow configuration.
- Update two-phase finalize calls to pass the repository and PR number.
- Remove PAT-based comment workarounds; the default GitHub token is the supported path.
- Pin examples and workflows to the release SHA.

## Verification

- The gate-bypass regression test fails on the old behavior and passes on the release candidate.
- Finalize rejects a bundle that omits changed files.
- Archive guard, secret redaction, single-comment, provider retry, and token-usage tests pass.
- The quickstart and documented CLI flags pass in a clean environment.
- CI is green at the release commit.
